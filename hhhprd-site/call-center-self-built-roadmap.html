自研软电话：功能架构、边界与阶段规划

从“供应商给什么用什么”转为“Dino 定义流程、策略和体验，供应商执行通信”

核心判断：自研重点是控制层、软电话交互、统一数据和 AI 侧边栏，不进入运营商网络、线路及基础语音基础设施。建议先在一个业务线跑通 V1，再推进 V2 和 V3。
换用目的 外呼原理 自研边界 AI 侧边栏 用户收益 阶段路线 收益总结

换用目的

当前

Sobot / Omicall 集成软电话

直接使用供应商集成好的软电话，UI、呼叫控制、状态和功能扩展依赖对方。

业务数据与交互体验割裂；一旦更换供应商，坐席操作和既有能力都要重新适配。

目标

Dino 薄软电话 + 多供应商 SDK 适配

CRM / Call Center → Dino 软电话壳 → 呼叫编排 → 供应商适配 → Sobot / Omicall SDK 与网络。

Dino 掌握业务流程、账号坐席关系、按业务线选工作台与号码、统一数据、侧边栏和 AI 扩展；电话网络、线路、并发、录音和基础转写继续由供应商提供。

外呼工作原理与供应商关系

Dino 控制与策略 供应商资源与执行 业务关系与上下文
坐席链
业务线→ 工作台 / 坐席供应商→ 坐席→ CRM 账号
号码链
业务线→ 号码供应商→ 线路→ 号码
两链汇合
CRM 账号绑定坐席+ 坐席配置的候选号码→ 选号策略→ 最优号码→ 坐席供应商 SDK→ 运营商网络

自研边界

Dino 需要掌握

决定业务体验、路由规则、数据标准和后续扩展。

软电话与侧边栏 统一 UI、呼叫状态、当前客户与业务上下文
账号－坐席－供应商 按业务线绑定，适配不同供应商 SDK
号码与选号策略 号码池、线路映射、候选号码与最优号码选择
统一呼叫数据 事件、状态、错误码、录音与逐字稿；结果回写线索、客户与跟进，归属仍由 CRM 决定
权限、合规与审计 号码、录音、导出权限，频控和操作日志
AI 扩展接口 实时转写、意图、话术、历史摘要与下一步动作

供应商继续提供

只提供专业通信能力，不承接 CRM 线索归属与销售归因。

  • 工作台供应商、坐席供应商与号码供应商
  • 运营商网络与实际语音通话
  • 电话号码、线路与号码资源
  • 并发容量、通话质量与可用性保障
  • 录音存储、基础语音转写
  • IVR、预测式外呼、语音机器人
Dino 控制面↔ 供应商适配层↔ 供应商通信面

AI 侧边栏：V3 目标态扩展

当前业务信息

通话前即可看到客户全貌。

  • 当前客户与归属业务线
  • 订单、权益与当前业务阶段
  • 最近跟进与关键待办
  • 历史有效信息摘要

AI 实时辅助

通话中直接辅助坐席决策。

  • 实时转写与对话内容分析
  • 客户意图识别与风险提示
  • 结合客户状态的推荐话术
  • 下一步动作建议与智能质检

依赖的基础能力

业务上下文与实时音频汇入同一侧边栏。

CRM 上下文服务 客户 / 订单 / 跟进 知识库与优秀话术 流式音频 / ASR 模型编排与知识检索 低延迟侧边栏推送

外呼卡点与坐席用户收益

现在：外呼前与通话中的卡点

多个步骤依赖人工完成，任一供应商或登录环节异常都会阻塞外呼。

登录 CRM→ 登录 / 授权软电话→ 人工绑定坐席→ 人工选择号码→ 供应商异常即中断→ 手工补录结果

自研后：CRM 内连续完成外呼

系统承担匹配、选号、状态回写和供应商路由，坐席专注沟通。

CRM 内一键起呼→ 自动匹配账号与坐席→ 自动选最优号码→ 可用供应商路由→ 状态、录音与结果回写
人工绑定 CRM 账号与坐席→ 自动匹配，减少坐席配置等待
重复登录、授权供应商软电话→ 从 CRM 直接起呼，免重复登录授权
人工判断并选择外呼号码→ 按业务线与选号策略自动匹配最优号码
供应商服务异常即无法外呼→ 健康检查与备用路由；具备备用坐席、号码和线路时可切换
通话结果手工补录、多处切换查资料→ 记录自动回写，客户上下文与通话同屏

供应商故障切换的前提：同一业务线已配置可用的备用坐席、号码和线路资源。

阶段功能架构

V0 · 看清能力 统一模型与数据口径
V1 · 统一入口 自研软电话与供应商适配
V2 · 规模化运营 任务、策略与线路运营
V3 · 智能化销售 AI 侧边栏与实时辅助
V0

基础建模

先看清能力与数据，再开始替换。

功能
  • 供应商能力盘点
  • CRM 账号、坐席、号码、线路模型
  • 呼叫事件与错误码归一
  • 基础通话记录、权限与审计
解决

能力边界不清、数据口径不一、故障无法定位。

收益

形成统一数据底座，为多供应商接入和后续替换做准备。

基础能力
  • 供应商 API / SDK 能力矩阵
  • 统一对象、事件与错误码字典
V1

自研软电话

统一入口，掌握路由与侧边栏框架。

功能
  • 多供应商 SDK 适配层
  • 业务线 → 账号 → 坐席 → 供应商
  • 号码候选池与选号策略
  • 统一拨号、挂断、重呼与 CRM 回写
  • 软电话壳与可扩展侧边栏框架
解决

供应商锁定、手工选号、通话状态和业务体验割裂。

收益

用户：免重复登录授权、免人工绑定坐席、免手动选号，CRM 内一键起呼。
平台：统一入口，可按业务线切换供应商并稳定追溯通话。

基础能力
  • 坐席、号码与业务线路由配置中心
  • 供应商适配与统一通话状态机
V2

外呼运营

从能打电话，升级到能规模化运营。

功能
  • 外呼任务、重拨与预约回拨
  • 时间窗、频控、黑名单与熔断
  • 供应商、线路健康与容量监控
  • 供应商异常提示与备用路由
  • 坐席效率与号码使用分析
解决

批量效率低、重复骚扰、异常不可控，运营数据无法归因。

收益

用户：任务、重拨和预约回拨由系统承接，异常有提示，减少重复操作与无效等待。
平台：提高外呼效率、合规性和容灾运营能力。

基础能力
  • 外呼任务引擎与策略规则中心
  • 稳定呼叫链路与运营数据底座
  • 备用供应商、线路与坐席资源
V3

AI 侧边栏

把通信入口变成销售实时助手。

功能
  • 实时转写、意图识别与话术推荐
  • 当前客户、订单、跟进与历史有效信息摘要
  • 下一步动作推荐与风险提示
  • 智能质检与销售辅导
解决

过度依赖个人记忆，新人上手慢，话术与服务质量不一致。

收益

用户：减少切页查资料与个人记忆依赖，新人更快进入有效沟通。
平台：提升转化和服务质量，把优秀经验沉淀为团队可复制能力。

基础能力
  • 流式音频 / ASR 与 CRM 上下文服务
  • 知识检索、模型编排与低延迟侧边栏推送

收益总结：坐席用户 + 平台架构

坐席 / CRM 用户

外呼步骤更少，从 CRM 直接起呼
免重复登录、人工绑定和手动选号
供应商异常有提示，可切换备用路由
通话状态、录音和结果自动回写
客户上下文同屏，减少切页与记忆负担

平台 / 架构

统一坐席体验
降低供应商切换成本
号码与业务线策略自主可控
统一事件、权限和审计
具备 AI 实时辅助扩展能力
边界：自研控制层、软电话交互和 AI 侧边栏，不自研运营商网络、线路、并发与录音基础设施。建议先用一个业务线验证 V1，再逐步替换现有集成软电话。
