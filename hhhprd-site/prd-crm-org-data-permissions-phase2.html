CRM组织数据权限二期

在一期已完成业务线、组织树和人员主组织的基础上，启用逐业务线数据授权，并按“本人主对象、本人线索关联记录、组织范围、动作处理范围和历史候选引用”统一定义所有客户数据入口。

目标与范围

目标

  • CC 的正常列表只展示本人线索，但能看到本人线索下由其他成员产生的全部跟进、通话、预约和任务。
  • 首次 CC 筛选、重新分配和转派目标可以出现其他成员，但不得因此扩大普通客户数据权限。
  • 管理者按授权组织子树或整条业务线查看线索、关联记录、看板和导出。
  • 线索、跟进、通话、用户、订单和业绩继续保存事件时组织快照，用于组织归属和历史统计。

做

  • 在成员账号中按业务线配置“本人 / 指定组织及下级 / 本业务线全部”。
  • 将数据权限接入销售、用户、订单、通话、看板、搜索、候选、导入和导出。
  • 区分普通数据范围、动作处理范围和历史候选引用。
  • 建立线索、跟进、通话、预约、任务和订单之间的访问继承关系。
  • 迁移当前业务归属，保持历史数据不反推。

不做

  • 不修改角色功能权限和既有动作权限项。
  • 不支持一条线索同时归属多个组织。
  • 不建设跨组织业绩分摊或复杂协作贡献。
  • 不按人员当前组织改写已结束业绩。
  • 不新增看板页签或导出格式。

前置条件

  • 一期业务线、组织树和成员主组织已完成配置并核对。
  • 每条在职成员的业务线均存在有效主组织。
  • 当前账号实际业务线权限和团队关系可导出，用于生成新旧权限差异。
  • 销售、用户、订单、通话、看板、搜索和导出具备同时切换条件。

数据授权

成员账号在每条业务线下按以下顺序配置：

业务线 → 数据授权 → 主组织

数据范围普通数据范围主组织默认值
本人本人当前或历史作为线索归属人的线索，以及这些线索关联的全部跟进、通话、预约、任务、用户和订单；本人作为操作人的事件也可查看保留已选主组织；未选择时要求手动选择
指定组织及下级可多选组织节点，覆盖所选节点及其后代；不包含业务线根节点直属数据和兄弟节点保留已选主组织或由管理员选择
本业务线全部业务线根节点直属数据、全部现有下级和未来新增下级自动默认业务线根节点，可调整

规则：

  • “本业务线全部”只覆盖当前选中的业务线；跨所有业务线属于独立全局能力。
  • 同一业务线内多条授权取并集，不同业务线分别判断。
  • 数据授权不改变主组织，主组织也不自动扩大数据授权。
  • 成员未配置有效主组织时可以查看已有授权数据，但不能接收新分配线索。
  • 查看、编辑、分配、转派、导出分别校验。

访问关系模型

二期不能只用“线索归属人”或“组织节点”一个条件判断所有页面，需要区分以下范围：

范围定义可以访问不可以访问
本人主对象本人当前或历史作为线索归属人的线索线索列表、详情、个人 Dashboard、关联用户和订单其他成员线索和公共池
本人线索关联记录挂在可访问线索下的业务事件该线索的全部跟进、通话、预约、任务和附件，即使由其他人产生其他不可访问线索下的记录
组织范围数据授权包含的业务线或组织子树范围内线索、关联记录、团队看板和明细范围外节点及其数据
动作处理范围分配、重新分配或转派时，用于选择源线索和目标人员的作业范围源线索、目标成员的姓名、组织和处理所需信息扩大普通列表、详情、Dashboard、用户中心或导出
历史候选引用首位 CC 等历史字段在当前可访问线索上的去重值作为筛选值或身份引用被引用人员的其他线索、资料和业务数据

判定顺序：

账号状态 → 功能权限 → 页面主对象范围 → 关联记录继承 → 动作处理范围或历史候选引用 → 字段与导出权限

CC 视角

CC 通常配置“本人”。普通列表和详情只展示本人线索；动作工作区和筛选候选可以出现其他人员，但不改变普通数据权限。

管理视角

管理者使用“指定组织及下级”或“本业务线全部”。记录可见性先由线索主对象确定，再继承该线索下的全部关联记录。

功能 / 场景管理者可见范围关联记录与操作边界
销售中心列表、线索详情、已付费授权组织子树或整条业务线内线索可按组织、当前 CC、首位 CC、状态和时间筛选
公海、待领取授权组织下的公共池只在组织和分配规则范围内操作
跟进、通话、预约、任务授权范围内线索关联的全部记录不限制记录操作人，可查看团队成员产生的记录
首位 CC / 当前 CC 筛选范围内线索中的实际字段值；首位 CC 可跨节点引用候选出现不等于获得该人员其他数据权限
分配、重新分配、转派源线索在管理范围内；目标成员在动作允许的组织范围内跨节点操作按功能权限和审计要求执行

导入、导出当前管理范围与动作权限的交集导入不能扩大已有客户读取范围

权限要求：

  • 普通 CC 的线索主列表和筛选结果只使用本人线索；当前页面的首跟 CC 候选可按历史事实跨节点展示。
  • 销售组长或管理者的“我的跟进”按业务线或授权组织范围展示组内线索。
  • “重新分配线索”使用动作处理范围；返回列表后恢复普通列表范围。
  • “退回公海”“更新跟进”“拨号”“修改试听课等级”和“添加会员时长”均要求对源线索有对应动作权限。
  • 下载数据使用当前筛选结果与导出权限交集。

组织层级筛选

  • 销售中心不保留“业务线”和“组织架构”两个并列筛选器，统一为一个组织树筛选器。
  • 业务线是一级根节点；选择整条业务线等价于按该业务线边界筛选，选择具体区/部/组等价于按该组织子树筛选。
  • 普通 CC 的组织树筛选只展示其有业务线权限的根节点，用于切换业务线；不会因选择根节点而扩大到组内其他 CC 的线索。
  • 管理者的组织树筛选展示其数据授权内的业务线根节点和组织节点。
  • 当前 CC 候选只来自所选组织范围与当前账号可访问线索的交集。
  • 首跟 CC 候选来自当前结果中实际出现过的历史首跟 CC，可跨组织节点，但不会扩大客户数据权限。
  • 业务线或组织切换后，原 CC 筛选值如不在新候选中自动清空。

首位 CC 是线索历史事实字段，不是当前操作人的组织授权范围。

页面筛选联动

  • 销售中心：原“国家/业务线”筛选升级为组织树选择，业务线为根节点；首跟 CC 和当前 CC 跟随所选组织联动。
  • 管理看板：原“业务线”筛选升级为组织树选择；“当前 CC”候选跟随所选组织联动。
  • 用户中心、订单中心和通话记录：已有业务线筛选统一改为组织树选择，业务线作为根节点。
  • 组织切换后，依赖组织范围的人员、首跟 CC、当前 CC 等筛选值需重新校验，失效值自动清空。

组织调整与人员调岗

  • 组织更换上级、批量转移成员或停用前展示成员、线索、分配规则和组织节点影响，并要求填写原因。
  • 修改人员某条业务线主组织时，如名下有对应业务线线索，保存前必须提示处理方式。
  • “直接带走”：保留当前线索归属人，将对应业务线线索的当前业务归属更新为人员新主组织；历史事件和组织快照不回写。
  • “留在原组织自动分配”：线索业务归属不变，原线索归属人清空，按原组织规则重新分配；无接收人时进入原组织待分配池。
  • 账号停用后立即失去登录、分配、领取、查询和导出权限。
  • 历史线索归属人、组织路径、作业和业绩保持原快照，并展示“已停用”。

历史与切换

  • 以正式切换时间区分旧一级业务线权限和新组织数据权限。
  • 切换前导出账号实际业务线范围，映射为逐业务线数据授权并生成差异。
  • 无法确认权限时默认不扩大范围，由管理员人工确认。
  • 当前仍有效的线索、用户、订单和通话，按切换时可确认的归属人和主组织建立当前业务归属。
  • 已结束线索、通话、跟进和订单不批量倒推组织。
  • 当前归属无法确认时保留业务线级或进入业务线待分配池。
  • 销售、用户、订单、通话、搜索、候选、看板、下钻和导出必须同时切换。
