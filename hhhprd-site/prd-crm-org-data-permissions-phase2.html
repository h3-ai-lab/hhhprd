CRM组织数据权限二期

在一期已完成业务线、组织树和人员主组织的基础上，启用逐业务线数据授权，并按“本人主对象、本人线索关联记录、组织范围、动作处理范围和历史候选引用”统一定义所有客户数据入口。

目标与范围

目标

  • CC 的正常列表只展示本人线索，但能看到本人线索下由其他成员产生的全部跟进、通话、预约和任务。
  • 首次 CC 筛选、重新分配目标 CC 和转派目标可以出现其他成员，但不得因此扩大普通客户数据权限。
  • 管理者按授权组织子树或整条业务线查看线索、关联记录、看板和导出。
  • 线索、跟进、通话、用户、订单和业绩继续保存事件时组织快照，用于组织归属和历史统计。

做

  • 在成员账号中按业务线配置“本人 / 指定组织及下级 / 本业务线全部”。
  • 将数据权限接入销售、用户、订单、通话、看板、搜索、候选、导入和导出。
  • 区分普通数据范围、动作处理范围和历史候选引用。
  • 建立线索、跟进、通话、预约、任务和订单之间的访问继承关系。
  • 迁移当前业务归属，保持历史数据不反推。

不做

  • 不修改角色功能权限和既有动作权限项。
  • 不支持一条线索同时归属多个组织。
  • 不建设跨组织业绩分摊或复杂协作贡献。
  • 不按人员当前组织改写已结束业绩。
  • 不新增看板页签或导出格式。

前置条件

  • 一期业务线、组织树和成员主组织已完成配置并核对。
  • 每条在职成员的业务线均存在有效主组织。
  • 当前账号实际业务线权限和团队关系可导出，用于生成新旧权限差异。
  • 销售、用户、订单、通话、看板、搜索和导出具备同时切换条件。

数据授权

成员账号在每条业务线下按以下顺序配置：

业务线 → 数据授权 → 主组织

数据范围普通数据范围主组织默认值
本人当前线索归属人为本人账号的线索，以及这些线索关联的全部跟进、通话、预约、任务、用户和订单；线索转派给其他成员后，原线索归属人立即失去该线索及关联记录保留已选主组织；未选择时要求手动选择

规则：

  • “本业务线全部”只覆盖当前选中的业务线；跨所有业务线属于独立全局能力。
  • 同一业务线内多条授权取并集，不同业务线分别判断。
  • 数据授权不改变主组织，主组织也不自动扩大数据授权。
  • 成员未配置有效主组织时可以查看已有授权数据，但不能接收新分配线索。
  • 查看、编辑、分配、转派、导出分别校验。
  • 公共池是业务线级共享资源，不属于“本人”线索；同一业务线根节点下所有有访问权限的人都能看到该业务线公共池，领取能力另按功能权限和组织规则校验。

判定顺序：

账号状态 → 功能权限 → 页面主对象范围 → 关联记录继承 → 动作处理范围或历史候选引用 → 字段与导出权限

组织树权限

组织树既是导航结构，也是数据授权边界，必须单独校验页面内可见和可操作范围。

能力规则
可见节点当前操作人每个数据授权节点的完整子树，加上从授权节点到业务线根节点的必要祖先路径
祖先节点只用于展开、定位和理解路径，只读展示；不产生成员、线索、看板或子节点编辑权限
可编辑节点仅限操作人明确授权节点及其下级；无权节点不能编辑、启用、停用或新增下级
父节点候选更换上级时，只能选择同业务线、当前可管理、非自身及自身后代、且不突破四级的节点
成员主组织候选只能选择当前操作人可管理业务线中的节点；必要祖先不可选
数据授权节点候选只能选择当前操作人可管理节点；“指定组织及下级”可从所选节点开始多选
批量转移目标只能是同业务线且位于当前操作人可编辑范围内的节点
非连续授权例如授权 A 部和 B 部时，只展示两棵子树及各自根路径，不自动包含中间的兄弟部门

角色边界：

  • 超级管理员可以查看和管理全组织树。
  • 业务线管理员可以查看和管理被授权业务线的组织树。
  • 区域/部门主管只能查看和管理授权节点子树；无权上级和兄弟节点不会因出现在路径中被赋予操作能力。
  • 普通 CC 不进入组织树配置，只使用主组织和业务线权限完成个人作业。

CC 视角

CC 通常配置“本人”。普通列表和详情只展示本人线索；重新分配目标和筛选候选可以出现其他人员，但不改变普通数据权限。

管理视角

管理者使用“指定组织及下级”或“本业务线全部”。记录可见性先由线索主对象确定，再继承该线索下的全部关联记录。

功能 / 场景管理者可见范围关联记录与操作边界
销售中心列表、线索详情、已付费授权组织子树或整条业务线内线索可按组织、当前 CC、首位 CC、状态和时间筛选
公海、待领取授权业务线根节点下的公共池同业务线共享可见；领取和分配仍按功能权限及规则控制
跟进、通话、预约、任务授权范围内线索关联的全部记录不限制记录操作人，可查看团队成员产生的记录
首位 CC / 当前 CC 筛选范围内线索中的实际字段值；首位 CC 可跨节点引用候选出现不等于获得该人员其他数据权限

用户、订单、通话、下钻与授权范围内线索关联的部分汇总、下钻和导出使用同一底层数据范围
组织、成员和操作日志授权组织内配置和日志必要祖先只用于定位，不产生数据或编辑权限
导入、导出当前管理范围与动作权限的交集导入不能扩大已有客户读取范围

组织筛选与联动

能力规则
统一控件销售中心、管理看板、团队监控、用户管理和订单管理统一使用同一个可搜索、可多选的组织树筛选器，不保留原生单选下拉作为替代
筛选入口不保留“业务线”和“组织架构”两个并列筛选器，统一为一个可搜索、可多选的组织树
树结构业务线为一级根节点；选择根节点包含根节点直属数据和全部现有、未来下级，选择具体区 / 部 / 组只包含该节点子树
默认展开进入页面时展开当前主组织所在业务线及其祖先路径，其他业务线、区和部默认收起，不改变用户已选筛选
搜索支持按组织名称和完整路径搜索；命中下级时自动展开必要祖先路径，祖先只用于定位
CC 可见树CC 只看到有业务线权限的根节点，用于切换业务线，不展开无权组织，也不会因选择根节点看到同组其他人的线索
管理者可见树展示数据授权节点子树及必要祖先路径；祖先只读且不可勾选，非连续授权不补齐中间兄弟节点
多选与覆盖可同时选择多个互不覆盖的节点；勾选父节点后，其后代显示为已覆盖并禁止重复勾选，移除父节点后恢复下级选择
首位 CC候选来自当前可访问结果中实际出现过的历史首位 CC，可跨组织节点；只作为筛选值，不扩大客户数据权限
当前 CC候选来自所选组织范围与当前账号可访问线索的交集，不枚举未出现且无权的人员
联动失效业务线或组织变化后，重新校验首位 CC、当前 CC 等依赖值；不在新候选中的值自动清空并刷新结果

页面筛选联动

  • 销售中心：原“国家/业务线”筛选升级为组织树选择，业务线为根节点；首跟 CC 和当前 CC 跟随所选组织联动。
  • 管理看板：原“业务线”筛选升级为组织树选择；“当前 CC”候选跟随所选组织联动。
  • 用户中心、订单中心和通话记录：已有业务线筛选统一改为组织树选择，业务线作为根节点。
  • 销售中心、管理看板、团队监控、用户管理和订单管理使用同一套组织树筛选交互、选中标签、搜索、展开和多选规则。
  • 组织切换后，依赖组织范围的人员、首跟 CC、当前 CC 等筛选值需重新校验，失效值自动清空。

组织调整与人员调岗

  • 组织更换上级、批量转移成员或停用前展示成员、线索、分配规则和组织节点影响，并要求填写原因。
  • 修改人员某条业务线主组织时，如名下有对应业务线线索，保存前必须提示处理方式。
  • “直接带走”：保留当前线索归属人，将对应业务线线索的当前业务归属更新为人员新主组织；历史事件和组织快照不回写。
  • “留在原组织自动分配”：线索业务归属不变，原线索归属人清空，按原组织规则重新分配；无接收人时进入原组织待分配池。
  • 账号停用后立即失去登录、分配、领取、查询和导出权限。
  • 历史线索归属人、组织路径、作业和业绩保持原快照，并展示“已停用”。

历史与切换

  • 以正式切换时间区分旧一级业务线权限和新组织数据权限。
  • 切换前导出账号实际业务线范围，映射为逐业务线数据授权并生成差异。
  • 无法确认权限时默认不扩大范围，由管理员人工确认。
  • 当前仍有效的线索、用户、订单和通话，按切换时可确认的归属人和主组织建立当前业务归属。
  • 已结束线索、通话、跟进和订单不批量倒推组织。
  • 当前归属无法确认时保留业务线级或进入业务线待分配池。
  • 销售、用户、订单、通话、搜索、候选、看板、下钻和导出必须同时切换。
