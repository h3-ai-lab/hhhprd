# 表单、字段与列表类 PRD 提示词

先读取 [`prd-generation.md`](prd-generation.md)。

## 适用信号

- 新增、修改、删除字段，或者字段含义、来源、默认值、可编辑性发生变化。
- 新增表单、详情区、列表列、筛选、排序、分组、批量操作或导出。
- 用户核心诉求是“更快找到、录入、比较或下载数据”。

## 现有 CRM 字段与顺序比对（强制）

设计字段、表单或列表前，必须先访问现有 CRM 中与本需求直接对应的页面，读取当前实际配置，不能只根据历史文档、模板或需求描述开始设计。

按以下顺序执行：

1. **定位现状页面**：找到当前业务对象、表单、详情页、列表或筛选入口，记录页面名称、路径和访问角色。
2. **读取字段与筛选器顺序**：按页面实际展示顺序记录字段，包括表单填写顺序、详情区分组与顺序、列表默认列顺序、筛选区入口与位置、筛选条件顺序；同时核对字段展示名称、类型、必填/默认值和是否可编辑。
3. **建立逐项比对**：将需求字段与现有字段逐一对应，标明“保留、新增、修改、删除、改名、合并、拆分、调序、待确认”，并写清变更原因。
4. **比对位置变化**：同时比较字段所在分组、步骤、列和筛选区，不能只比较字段是否已经存在。新增筛选器时，必须记录现有筛选区的位置、分组和同类筛选器的相对顺序。
5. **确认差异结论**：先输出现状顺序、目标顺序和差异，再设计页面与交互；新方案不能在没有说明的情况下改变现有顺序。
6. **记录访问边界**：无法进入页面或缺少查看权限时，明确记录缺少的页面与权限，将现状顺序列为待确认。不得用推测顺序冒充实际配置。

PRD 中至少包含一张字段顺序比对表：

| 现状顺序 | 字段 | 现状位置 | 比对结果 | 目标顺序/位置 | 变更原因 |
|---|---|---|---|---|---|
| | | 表单/详情/列表/筛选 | 保留/新增/修改/删除/改名/合并/拆分/调序/待确认 | | |

仅新增字段时也必须核对现有顺序和插入位置；仅调整列表时也必须读取当前默认列及其顺序。已有字段被删除、改名、合并或拆分时，还要说明历史数据和已有筛选条件的兼容方式。

新增筛选器时，必须先进入现有 CRM 的对应筛选区，识别同类筛选器所在的区域、分组和相对位置，再将新筛选器加入相同的位置和分组，不能默认追加到筛选区末尾。PRD 的字段顺序比对表需写清“现状筛选区/位置 → 目标筛选区/位置”。

## 字段设计必须写清

每个字段至少说明：

- 展示名称和业务含义。
- 数据类型和可选值。
- 是否必填、默认值和示例。
- 数据来源、快照或实时读取。
- 是否可编辑，由谁、在哪个状态可编辑。
- 空白、未知、历史缺失和权限不足如何展示。
- 与现有字段的区别，禁止用两个字段表达同一含义。

字段表建议列：`字段、含义、类型/枚举、必填、默认值、来源、可编辑规则、权限、异常展示`。

## 列表与交互

- 列表默认列、列顺序、字段格式和空值。
- 搜索范围和搜索字段，不能只写“支持搜索”。
- 筛选区位置、新增筛选器所在分组和相对顺序、筛选条件、组合逻辑、默认筛选和跨页保留规则。
- 排序字段、升降序、多字段优先级和分页规则。
- 空态、加载态、无权限和筛选无结果的区别。
- 批量选择、批量操作、二次确认和失败反馈。
- 导出是否使用当前筛选、是否包含全部列、字段顺序、时区和权限范围。

## RBAC 权限数据

新增字段、列、筛选或数据列表时，必须同时读取 [`04-permission-audit.md`](04-permission-audit.md)，并写明：

- 页面、列表、筛选和行级数据的可见范围。
- 查看、新增、编辑、批量操作、导入和导出分别对应哪些角色。
- 敏感字段是否明文、脱敏或不可见，是否允许导出。
- 筛选和分配候选项是否只返回当前角色有权限的对象。
- 权限不足、无数据和筛选无结果在页面上的不同表现。
- 本次新增、修改或复用了哪些 RBAC 权限数据。

## PRD 组织

1. 要解决的查找、录入或操作问题。
2. 现有 CRM 字段、展示位置与顺序比对。
3. 目标字段字典及顺序调整结论。
4. 列表、搜索、筛选、排序和分页。
5. 编辑、批量操作和导出。
6. RBAC 权限数据、字段权限和导出范围。
7. 历史数据和异常。
8. 待确认。

## 内部检查

- 每个字段只有一个明确业务含义。
- 已访问现有 CRM 对应页面并核对实际字段顺序，完成的对比结论与本次变更一致。
- 搜索、筛选、排序、分页和导出范围一致。
- 列表可用不等于字段可见或允许导出，RBAC 权限已逐项说明。
- 字段来源和历史缺失不会用猜测值填补。
- 是否混入数据库设计、接口实现或验收条件。
