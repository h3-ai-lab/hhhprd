# 权限与审计类 PRD 提示词

先读取 [`prd-generation.md`](prd-generation.md)。

## 适用信号

- 新增角色、功能权限、数据权限、团队/区域/业务线隔离。
- 手机号、录音、导出、赠送权益等敏感能力。
- 需要操作留痕、审核、撤销或合规追溯。

## 权限模型必须分开

- 功能权限：能不能进入页面、看到按钮、执行操作。
- 数据权限：能看到哪些业务线、团队、用户、订单或线索。
- 字段权限：敏感字段是否明文、脱敏或完全不可见。
- 候选项权限：筛选、分配、搜索时是否能看到无权对象。
- 下载权限：页面可看是否等于可以批量导出。

不能只写“管理员可见”，必须说明角色、数据范围和例外。

## RBAC 权限数据必须完整

新增功能或数据列表时，PRD 必须输出可落入 RBAC 管理的权限数据，而不是只描述页面效果。

### 功能权限

| 页面/资源 | 操作 | 业务含义 | 默认角色 | 数据范围 | 审计 |
|---|---|---|---|---|---|
| | 查看/新增/编辑/删除/审批/批量/导入/导出 | | | | |

### 字段与数据权限

| 字段组/列表 | 可见角色 | 编辑角色 | 脱敏/隐藏 | 可导出 | 候选范围限制 |
|---|---|---|---|---|---|
| | | | | | |

### 权限数据变更

| 变更类型 | 权限层级 | 权限项 | 业务说明 | 默认角色/数据范围 | 是否新增审计 |
|---|---|---|---|---|---|
| 新增/修改/复用 | 菜单/页面/动作/数据/字段/导出 | | | | |

规则：

- 一个动作只能对应一个明确权限项；页面可进入不代表可以执行所有动作。
- 列表筛选、候选人和分配对象必须遵守数据权限，不能通过搜索看到无权对象。
- 查看权限与导出权限分开；批量操作与单项操作也分开。
- 新增权限必须说明默认角色；修改权限必须说明对现有角色和历史成员的影响。
- 复用现有权限必须列出权限项，不得只写“沿用现有权限”。
- 删除、赠送权益、重试发放、撤销和导出等敏感动作必须记录审计。

## 审计必须回答

- 哪些操作记录审计，成功、失败和未授权尝试是否记录。
- 审计字段包括什么：操作人、时间、对象、操作类型、变更前后、原因和来源。
- 哪些审计不可修改或删除，保留多久。
- 权限撤销后多长时间生效，历史数据和已生成文件如何处理。

## 离职账号与数据交接（强制）

涉及员工离职、账号停用或组织关系变化时，必须同时定义权限、业务数据和审计处理。

- 停用账号后立即撤销登录、菜单、操作、查询、导出和自动化任务权限，已登录会话与已生成下载链接按现有安全策略失效。
- 不删除员工身份和历史操作记录；业务数据中的负责人姓名、ID 和团队快照继续保留。
- 当前持有的线索、订单、客户、待办和报表访问权必须完成转派、回收或主管托管，并明确处理失败时的兜底责任人。
- 新负责人获得当前业务处理权，不自动继承原负责人的历史绩效归属或其他业务对象权限。
- 历史报表仍可按原负责人、原团队和离职前时间范围查询，并按报表规则显示“离职/停用”。
- 批量回收、转派和人工接管必须记录操作人、范围、原负责人、新负责人、结果和失败原因。

## PRD 组织

1. 敏感能力和风险。
2. RBAC 功能权限矩阵、字段与数据权限、权限数据变更。
3. 数据范围与字段脱敏。
4. 审计事件与保留。
5. 无权限、账号停用、离职交接和历史兼容。

## 内部检查

- 菜单、页面、候选项、接口和数据范围是否一致。
- 查看权限是否被错误等同于导出权限。
- 候选对象、筛选结果和列表数据范围是否一致。
- 离职或停用账号是否立即失权，且其业务数据、任务和历史记录已有明确交接。
- 敏感操作是否都有审计。
- 是否混入权限代码、鉴权实现或验收清单。
