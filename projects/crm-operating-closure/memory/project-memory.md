# CC 快捷工作队列 Memory

## Scope Update

- 原“CRM经营闭环规划”管理层汇报已拆分为独立规划项目，公开入口为 `crm-operating-closure.html`。
- 本项目收敛为销售中心内的 CC 快捷工作队列，不新增页面、菜单、持久化队列字段或独立任务中心。

## Confirmed Facts

- 业务线下表已经管理线索、接通、预约、到课、咨询、PL、定金、尾款和收入。
- 业务核心运动链路为：线索 → 接通 → 预约 → 预约确认 → 到课 → 咨询完成 → PL → 定金 → 尾款 → 订单与收入。
- CC 的核心问题是“今天处理谁、为什么处理、下一步做什么”。
- 管理者的核心问题是“团队卡在哪、谁需要帮助、哪类问题正在重复发生”。
- 现有 CRM 已具备用户、线索、销售跟进、订单、外呼、组织和看板的基础能力。
- 当前主要风险是客户事件分散、任务触发不完整、指标口径不统一和支付状态不一致。

## Decisions

- 本期以 CC 销售中心快捷筛选为唯一范围，管理干预、经营日报和学习履约不在本期实现。
- CC 和管理者继续使用现有销售中心、客户事件、任务结果和数据权限，不维护两套数据。
- 首期提供 7 个一级快捷队列；P4“今日新注册高意向待接通”和 P6“历史未联系待接通”分别独立展示，不使用合并入口或子筛选。
- 同一线索只进入一个主工作队列，按 P0 到 P6 的优先级唯一归属。
- P1 仅表示客户已到课但体验课程未完成，不表示咨询未完成。
- P4 只包含当天首次注册、购买意向高、注册后尚未有效外呼的线索；P6 只包含此前注册且历史上尚未建立有效联系的线索。
- 队列由现有数据计算，不新增持久化字段，不改变列表字段和排序能力。
- 到课与咨询完成是两个独立状态，不使用一个字段同时表达。
- PL 是支付意向等级，不是系统计算的概率；PL 100 表示已付定金，PL 80 表示明确承诺付款，PL 50 表示仍有顾虑且未拒绝。
- 管理看板首先服务于发现卡点与发起干预，不以增加图表数量为目标。
- 学习进度和续费属于客户价值延伸，依赖销售闭环和统一事件底座。
- 正式产品同时服务 CC 个人行动和管理者团队经营，不把通用配置能力继续无序堆入 CRM。

## Glossary

- 今日行动：根据客户事件、任务到期、阶段风险和业务规则生成的 CC 工作队列。
- PL：支付意向等级，使用 PL 100、PL 80、PL 50、Pending、Rejection、Follow Up 等业务状态。
- 到课：客户按预约实际参加体验课。
- 咨询完成：体验结束后，顾问已完成约定的咨询动作。
- 管理干预：管理者基于目标差距或异常任务，对团队、CC 或客户采取可追踪动作。
- 经营日报：由客户事件、任务处理和管理干预自动汇总的工作与经营摘要。
