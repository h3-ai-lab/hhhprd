# 拉新裂变 MVP Memory

## Confirmed Facts

- 当前手工链路为 CC 联系推荐人，推荐人线下邀请好友注册；好友在 App 购买套餐后，CC 在 CRM 给推荐人增加免费会员并手写 referral 备注。
- 业务希望去掉奖励发放的人工确认；当前 CRM 已经可以手工加会员，把绑定和发奖混在一起没有价值。
- 关系绑定必须前置且独立：被推荐人完成注册后，由目标归属 CC 使用其用户 ID 建立推荐关系。
- MVP 阶段推荐人与被推荐人的关系仍由 CC 在 CRM 录入；用户端邀请链接和自动绑定放到后续版本。
- 首版需要识别好友推荐和社媒推荐来源，并能看到操作 CC、推荐人、被推荐人、人数和 GMV。
- 现有“添加会员”弹窗包含开通类型、有效期天数、开通原因和确认操作。

## Decisions

- 新建独立“拉新关系维护”入口，关系绑定与添加会员、权益发放分离。
- CC 在绑定阶段只录入被推荐人用户 ID 并确认关系，不选择奖励、不填写天数、不调用权益服务。
- 被推荐人必须是正式注册用户；未注册或游客用户不能绑定。
- 新注册判定为 `campaign_start_at ≤ registered_at ≤ binding_time`。
- 绑定成功后提示被推荐人的当前归属 CC；当前归属 CC 使用销售中心“重新分配线索”完成转移后关系才生效。
- 待转移期间不生成奖励；转移完成后补评估绑定后已发生且尚未发放的课程、订单和社媒推荐事件。
- 系统自动核验被推荐人的有效付费会员订单，并带出推荐奖励；CC 不再手工判断订单和奖励时长。
- 一个被推荐用户只能绑定一个推荐人；同一对推荐人与被推荐人只能存在一条有效关系。
- 推荐人可以有多个被推荐用户。
- 本版支持被推荐人首课完课后 +14 天，以及首次购买 3/6/12 个月后自动发放 +1/+2/+3 个月。
- 首课奖励以课程服务最终 `COMPLETED` 事件触发；预约、进行中、取消、未到课、改期和技术失败不触发。
- 社媒推荐由 CC 代用户在 CRM 登记，记录用户、课堂证据、平台、内容类型、内容链接或文件、授权和登记 CC；审核有效 +5 天，最终未选中 +15 天，官方选中 +2 个月。
- 本期不建设 App 用户自助投稿；CC 提交前完成用户、课堂、链接和重复内容校验，通过后只生成待审核投稿。
- 同一社媒投稿只能产生一次基础奖励，并只能被判定为官方选中或未选中；状态变化按奖励事件幂等追加。
- “拉新关系维护”和“拉新归因”合并为一个“拉新关系”页面和一个统一列表。
- 销售中心“我的跟进 / 已付费”的更多菜单新增“维护拉新关系”，自动带入当前推荐人。
- 看板默认按关系绑定时间统计，也可切换归因订单支付时间；GMV 使用每条关系对应的唯一归因订单。
- 缺失的历史推荐关系不通过备注或行为猜测回补。
- 所有用户、业务线、新注册、推荐唯一性、订单、奖励规则和权限校验必须在提交前完成。
- “发放失败”只用于校验通过后权益发放阶段的系统异常，不承接业务校验失败。
- 发放失败原因只使用权益服务不可用、请求超时、结果未知、服务内部错误、业务数据访问失败和未知系统异常。
- 自动奖励必须先创建零金额赠送订单，再由订单驱动会员权益开通；不能跳过订单直接修改会员时长。
- 赠送订单沿用现有添加会员的订单创建、权益联动与来源业务键幂等逻辑。
- 每个奖励事件最多生成一笔赠送订单；订单创建后重试继续使用原订单。
- 赠送订单金额为 0，不进入 GMV、实付收入或付费用户口径。
- “增加用户时长”是既有后台操作，不属于拉新或社媒推荐奖励链路，不承担奖励归因。

## Glossary

- 推荐人：接受 CC 活动沟通并向朋友推荐产品的现有用户。
- 被推荐人：经推荐人邀请、通过用户 ID 与推荐人同业务线关联，并满足活动新注册判定的正式注册用户。
- 归因订单：每条推荐关系唯一关联的、用于判定推荐奖励和计算 GMV 的有效付费会员订单。
- 操作 CC：实际提交本次权益和关系记录的 CRM 账号。
- 归属 CC：本次拉新业绩计入的 CC，默认取推荐人当前线索负责人，允许有权限的管理者调整。
