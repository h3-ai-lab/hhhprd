# 拉新裂变 MVP Memory

## Confirmed Facts

- 当前手工链路为 CC 联系推荐人 B，B 线下邀请 C，C 在 App 购买套餐后，CC 在 CRM 给 B 增加免费会员并手写 referral 备注。
- 业务希望去掉奖励发放的人工确认；当前 CRM 已经可以手工加会员，把绑定和发奖混在一起没有价值。
- 关系绑定必须前置且独立：先建立 B → C 关系或手机号预绑定，再由业务事件自动发放权益。
- MVP 阶段 B 与 C 的关系仍由 CC 在 CRM 录入；C 端邀请链接和自动绑定放到后续版本。
- 首版需要识别 referral / social post 来源，并能看到操作 CC、推荐人、被推荐人、人数和 GMV。
- 现有“添加会员”弹窗包含开通类型、有效期天数、开通原因和确认操作。

## Decisions

- 新建独立“拉新关系维护”入口，关系绑定与添加会员、权益发放分离。
- CC 在绑定阶段只录入 C 手机号并确认关系，不选择奖励、不填写天数、不调用权益服务。
- C 尚未注册时可保存待注册手机号预绑定，注册后自动关联并进入推荐归属。
- 被推荐人手机号必须以推荐人 B 所属业务线为匹配范围；同业务线唯一命中才可继续。
- 系统自动核验 C 的有效付费会员订单，并带出推荐奖励；CC 不再手工判断订单和奖励时长。
- 一个被推荐用户只能绑定一个推荐人；同一对 B/C 只能存在一条有效关系。
- 推荐人 B 可以有多个被推荐用户。
- 本版支持被推荐人首课完课后 +14 天，以及首次购买 3/6/12 个月后自动发放 +1/+2/+3 个月。
- 首课奖励以课程服务最终 `COMPLETED` 事件触发；预约、进行中、取消、未到课、改期和技术失败不触发。
- 社媒推荐记录平台、内容类型、链接、授权和状态；发布 +5 天，有效未选中 +15 天，官方选中 +2 个月。
- 同一社媒内容只能被判定为官方选中或有效未选中，状态变化按奖励事件幂等追加。
- “拉新关系维护”和“拉新归因”合并为一个“拉新关系”页面和一个统一列表。
- 销售中心“我的跟进 / 已付费”的更多菜单新增“维护拉新关系”，自动带入当前推荐人。
- 看板默认按关系绑定时间统计，也可切换归因订单支付时间；GMV 使用每条关系对应的唯一归因订单。
- 缺失的历史推荐关系不通过备注或行为猜测回补。
- 所有用户、业务线、手机号唯一性、订单、推荐关系、奖励规则和权限校验必须在提交前完成。
- “发放失败”只用于校验通过后权益发放阶段的系统异常，不承接业务校验失败。
- 发放失败原因只使用权益服务不可用、请求超时、结果未知、服务内部错误、业务数据访问失败和未知系统异常。
- 自动奖励必须先创建零金额赠送订单，再由订单驱动会员权益开通；不能跳过订单直接修改会员时长。
- 赠送订单沿用现有添加会员的订单创建、权益联动与来源业务键幂等逻辑。
- 每个奖励事件最多生成一笔赠送订单；订单创建后重试继续使用原订单。
- 赠送订单金额为 0，不进入 GMV、实付收入或付费用户口径。

## Glossary

- 推荐人 B：接受 CC 活动沟通并向朋友推荐产品的现有用户。
- 被推荐人 C：由 B 推荐、手机号与推荐人同业务线唯一匹配，并完成有效付费会员购买的注册用户。
- 归因订单：每条推荐关系唯一关联的、用于判定推荐奖励和计算 GMV 的有效付费会员订单。
- 操作 CC：实际提交本次权益和关系记录的 CRM 账号。
- 归属 CC：本次拉新业绩计入的 CC，默认取推荐人当前线索负责人，允许有权限的管理者调整。
