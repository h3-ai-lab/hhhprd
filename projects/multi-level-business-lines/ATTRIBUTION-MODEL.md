# 多级业务线：简化归属模型

> 一人一个功能角色、一条数据授权、一个行政主组织；组织最多四层；任意节点都可直接承接业务；数据产生在哪个节点，就记录并统计在哪个节点。

## 1. 固定组织层级

```text
国家
└── 区
    └── 部
        └── 组
```

规则：

- 最多四层，不要求每条分支都建满四层。
- 国家、区、部、组都可以直接承接线索并产生业绩。
- 不要求数据必须落到“组”，不引入最小节点判断。
- 父节点查询包含自身直属数据和全部下级数据。

## 2. 账号配置

同一业务线内，每个账号只有：

- 一个功能角色。
- 一条数据授权。
- 一个行政主组织。

一条数据授权可以包含多个组织节点，例如 A部+B部，但它只决定账号能操作哪些数据，不改变行政主组织。

## 3. 线索归属

线索唯一记录当前运营归属组织，并保存完整路径快照。

| 场景 | 线索归属 |
|---|---|
| 从 A部公共池领取 | A部 |
| 命中 A部分配规则 | A部 |
| 从 B部创建或领取 | B部 |
| 无明确来源，直接分给个人 | 接收人的行政主组织 |
| 从区级公共池领取 | 区级节点 |

外呼、跟进、预约和成交继承线索当前运营归属，不要求在每次操作时重新选择组织。

## 4. 组织变化

- 线索、外呼、跟进和成交按发生时点保存组织路径快照。
- 人员调组只影响后续新分配线索，不回写历史。
- 转派成功时更新线索当前归属，新事件使用新路径，旧事件保留原路径。
- 组织改名、拆分或合并不追溯改写已结束历史。

## 5. 查询与业绩

```text
组业绩 = 组自身数据
部业绩 = 部自身数据 + 所属各组
区业绩 = 区自身数据 + 所属各部
国家业绩 = 国家自身数据 + 所属各区
```

- 操作数据按发生时的组织快照统计。
- 成交业绩按线索在成交时的运营归属组织统计。
- 个人视图可汇总本人跨越多个组织产生的数据。
- 团队和区域视图只按组织路径统计，不复制到两个组织。
- 首期不做跨组织业绩分摊。

## 6. 示例

U2：

- 功能角色：1区管理员兼销售。
- 行政主组织：1区。
- 数据授权：1区及全部下级，因此可以操作 A部、B部和所属组。

如果 U2 从 A部公共池领取线索，归属 A部；从 B部领取，归属 B部；无来源直接分配给他，归属1区。后续外呼、跟进和成交都沿线索当前组织统计。
