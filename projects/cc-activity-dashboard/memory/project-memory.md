# CC活跃度看板项目 Memory

## Confirmed Facts

- 项目名称为“CC活跃度看板”，需求编号为 REQ-DASH-008。
- 现有需求来自 Sales Tracking – Sales Consistency & Early Warning System 截图，目标是尽早发现 CC 出单节奏异常。
- 截图样例统计周期为 2026-11-09 至 2026-11-15，共 7 天。
- 截图中的有效样本为 18 名 CC，排除 3 名标记为 Need break 的 CC。
- 每个 CC 展示最近成交日期、连续未成交天数、平均出单间隔和最近 7 天每日成交记录。
- 汇总指标为 Recently Sales Activity、Sales Consistency 和 High-risk CCs。
- 平均出单间隔按“统计周期天数 ÷ 有成交的日期数”计算；7 天周期中成交 5、4、3、2、1 天分别对应 1.40、1.75、2.33、3.50、7.00 天。
- 项目需要进入 CRM，并为销售管理者提供按业务线、团队和个人查看的能力。
- 本期入口确定为管理看板新增“CC活跃度”页签，页面筛选顺序为业务线、销售团队、CC、统计周期。
- 有效成交定义为支付成功、未被取消或全额退款的有效订单；以首次支付成功时间形成成交日。
- 三项汇总指标按 CC 人数去重，不能与订单笔数混用。
- 历史周期绑定当期规则版本，后续修改阈值不追溯重算。

## Decisions

- 本期采用配置化业务口径，不开放任意公式、SQL 或自由计算表达式。
- 统计周期、时间口径、成交事件、样本范围、指标阈值和展示文案可以配置。
- 有效订单约束、订单去重、CC 归属、用户身份匹配和核心公式保持受控。
- 配置变更需要版本、生效日期、适用团队和审计记录。
- 休息 CC 本期不纳入，Need break 相关流程和自动排除进入最终待办。
- 已生成单文件 PRD 和中英文交互原型，项目进入待评审阶段。
- 默认统计周期为最近 7 个完整自然日，近期活跃观察窗口为 2 个完整自然日。
- 一致性默认门槛为 High ≤ 1.75 天、Good ≤ 2.33 天、Needs Improvement ≤ 3.50 天。
- 风险默认门槛为 Healthy 0 天、Early Warning 1 天、At Risk 2–3 天、Critical ≥ 4 天。

## Proposed Defaults

- 默认周期为最近一个完整的 7 个自然日。
- Recently Sales Activity 默认观察最近 2 个完整日。
- 一致性分层默认按平均出单间隔配置：High 不高于 1.75 天，Good 不高于 2.33 天，Needs Improvement 不高于 3.50 天，Low 高于 3.50 天。
- 风险分层默认：Healthy 为 0 天，Early Warning 为 1 天，At Risk 为 2–3 天，Critical 为 4 天及以上。
- High-risk CCs 默认等同于 Critical。

以上为立项基线，进入 PRD 前仍需业务负责人确认。

## Glossary

- CC：负责客户沟通、商机推进和成交的销售人员。
- 有效成交：计入看板成交统计的业务事件，具体数据源和状态待 PRD 前确认。
- 成交日：某 CC 在某日内至少产生一笔有效成交；同日多笔只计一个成交日。
- 平均出单间隔：统计周期天数除以成交日数。
- 最近活跃：最近 N 个完整日内至少出现一个成交日。
- Need break：经审批的休息或暂停销售状态。
