# CRM 线索质量分析 Memory

## Confirmed Facts

- 数据中心只作为广告渠道、活动、广告组和广告字段的数据来源，本项目不在数据中心建设新页面。
- 本需求落地在 CRM 用户中心、销售中心和 CRM Dashboard。
- 分析对象是 CRM Leads；不关注花费、曝光、点击、CTR、CPL、ROAS 等投放侧结果。
- 用户中心和销售中心现有列表均没有排序入口，本需求不新增列排序。
- 管理看板现有核心口径按注册批次统计、按用户或线索唯一 ID 去重。
- 用户、线索、外呼、预约、课程完成和订单均使用现有 CRM 业务事实。

## Decisions

- 广告层级固定为：广告渠道 → 活动 → 广告组 → 广告。
- 每条用户或线索保存首次有效广告归因快照，后续新广告触点不覆盖原归因。
- 广告稳定 ID 用于关联与筛选，名称仅用于展示；名称变化不改变历史归因关系。
- 广告筛选使用级联选择，上级变化会清理不再有效的下级选择。
- 广告渠道、活动、广告组和广告分别支持多选；业务线筛选保持单选。
- 批量分配线索时，若选中线索跨越多个业务线，分配规则无法确定唯一目标范围，阻止提交。
- 用户中心按用户展示广告归因；销售中心按线索展示同一用户的归因快照。
- 管理看板指标沿用现有注册批次、业务线、CC 和有效状态规则；仅在“转化总览”和“销售跟进”的“转化明细”中，为“先按 / 再按”增加“投放”分组方式。
- 支付结果页不增加投放分组，顶部筛选区不新增广告筛选器。
- 广告投放成本及媒体效果不进入 CRM。
- 未获得有效广告归因的数据显示“未归因”，不得自动推断为自然流量或某个广告。
- 员工离职、停用或转派不改变线索的广告归因；历史责任人仍按现有管理看板规则可追溯。
- 本期不建设按角色自定义筛选器、自定义字段和默认折叠，筛选区拥挤问题后续单独立项。

## Glossary

- 广告渠道：广告平台或媒体来源，对应 `media_source`。
- 活动：广告平台中的 Campaign。
- 广告组：广告平台中的 Ad Set / Ad Group。
- 广告：广告平台中的具体 Ad，使用 `ad_id` 作为稳定标识。
- 广告归因：用户或线索首次有效广告触点对应的四级广告信息。
- 线索业务表现：该来源下的 Leads 在接通、预约、体验课完成和付费等业务节点的结果。
