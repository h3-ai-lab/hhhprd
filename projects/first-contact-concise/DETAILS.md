# 引入首跟节点&首跟看板-2：研发与 AI 展开说明

> 需求编号：REQ-CC-002｜版本：V1.0｜更新时间：2026-11-11
> 本文档只展开 [PRD.md](PRD.md) 中的已确认决策，不新增业务范围。

## 1. 字段字典与排序

列表默认按首次分配时间倒序，并以用户 ID 作为稳定的次级排序。用户主动切换排序后，翻页、切换页签和下载均保持当前排序。

| 字段 | 业务规则 | 排序要求 |
|---|---|---|
| 首跟 CC | 首次成功分配时的负责人；保存姓名快照和 CC ID，转派不覆盖 | 支持；按姓名升序/降序，空值置后 |
| 当前 CC | 当前负责人；沿用现有领取和转派规则 | 支持；按姓名升序/降序，空值置后 |
| 首次分配时间 | 首次成功取得归属的时间，带业务线时区 | 支持；升序/降序，空值置后；默认降序 |
| 首次外呼时间 | 首跟 CC 的第一条外呼记录时间，不区分结果 | 支持；升序/降序，空值置后 |
| 首次接通时间 | 首跟 CC 的第一条接通记录时间 | 支持；升序/降序，空值置后 |
| 外呼次数 | 线索关联且已同步的外呼记录总数 | 支持；数值升序/降序，空值按 0；默认降序 |
| 外呼接通次数 | 外呼记录中状态为接通的次数，不得大于外呼次数 | 支持；数值升序/降序，空值按 0 |
| 跟进阶段 | 沿用现有销售阶段及业务顺序 | 条件排序；按配置的业务顺序，不按文字排序 |
| 用户 ID | 用户唯一识别字段，用于搜索和核对 | 不支持；主要用于精确查找 |
| 手机号 | 联系方式，用于搜索和外呼 | 不支持；排序没有业务价值 |
| 学生姓名 | 用户识别字段 | 不支持；主要用于搜索 |
| 购买意向 | 现有意向分类 | 不支持默认排序；通过筛选查看 |
| 用户状态 | 现有付费/体验状态 | 不支持默认排序；通过筛选查看 |
| 用户类型 | 现有用户分类 | 不支持默认排序；通过筛选查看 |
| 年龄段 | 现有课程年龄分组 | 条件排序；可按配置的业务年龄顺序升序/降序 |
| 课程等级 | 现有课程等级 | 条件排序；可按 L1 到后续等级的业务顺序排序 |
| 登录账号 | 用户识别字段 | 不支持；主要用于搜索 |
| 渠道来源 | 现有渠道来源及落地页 | 不支持默认排序；通过筛选比较 |

字段展示规则：

- 首跟 CC 离职或改名后保留原 CC ID 和姓名快照，并展示当前账号状态。
- 首次分配时间、首次外呼时间和首次接通时间精确到分钟，并按业务线时区展示。
- 无首次外呼或接通记录时显示“—”。
- 外呼次数和接通次数无记录时显示 0；数据未同步时显示最近一次成功值。
- 首跟 CC 和三个首次时间均为只读事实字段，不允许业务人员直接编辑。

## 2. 列表与筛选

### 列表顺序

现有字段及默认顺序保持不变：

`用户 ID → 学生姓名 → 购买意向 → 用户状态 → 用户类型 → 年龄段 → 课程等级 → 登录账号 → 渠道来源-落地页`

在现有来源字段之后、操作列之前依次增加：

`首跟 CC → 当前 CC → 跟进阶段 → 首次分配时间 → 首次外呼时间 → 首次接通时间 → 外呼次数 → 外呼接通次数`

部分页签已有的渠道来源-App、渠道 code 等字段保持原位置；操作列始终位于最右。

### 筛选区现状与目标位置

| 区域 | 现有内容 | 本期调整 |
|---|---|---|
| 第一行 | 搜索、国家、购买意向、CC | 在 CC 前增加首跟 CC |
| 第二行 | 当前跟进阶段、年龄段、课程等级、渠道来源-落地页、渠道来源-App | 保持不变 |
| 第三行 | 用户状态、销售咨询预约、预约外呼、注册日期及起止日期 | 在现有日期类型中增加首次分配时间 |
| 第四行 | 无 | 增加首次外呼状态、首次接通状态、外呼次数区间、外呼接通次数区间 |

筛选与列表规则：

- 搜索范围沿用手机号、用户 ID 和姓名，不扩大到新增字段。
- 国家、首跟 CC、当前 CC、阶段、状态和次数区间同时生效。
- 外呼次数和接通次数支持大于等于 0 的整数区间，起止边界均包含。
- 首次分配时间未知的线索不命中任何首次分配时间范围。
- 切换页签、翻页和排序时保留已应用筛选。
- 无结果、无权限、加载失败和数据未同步分别展示对应状态。

## 3. 业务规则

### 首跟节点

- 自动分配到具体 CC、公海人工领取和组长直接分配成功，均视为首次取得归属。
- 首跟 CC 和首次分配时间只写入一次。
- 后续转派只更新当前 CC 和分配历史，不覆盖首跟节点。
- 回池、再次领取、退款和订单状态变化不重置首跟节点。
- 并发领取只能有一个成功结果，未成功事件不得写入首跟节点。

### 首次外呼与接通

- 首跟 CC 的第一条有效外呼记录写入首次外呼时间，不区分接通、拒接、无人接听或呼叫失败。
- 首跟 CC 的第一条接通记录写入首次接通时间。
- 首次外呼次数和首次接通次数按外呼记录 ID 去重。
- 跟进事件使用跟进记录 ID 去重，重复回调不重复计数。

### 历史与兼容

- 历史数据只从可验证事件回填，无法确认时显示“历史未知”。
- 导入 leads 默认只记录当前负责人，不据此推断首跟 CC。
- 人工修复历史首跟数据必须保存批次、来源、操作人和修复时间。

## 4. 下载

下载使用当前筛选结果和当前排序，不受分页限制。文件至少包含：

`lead_id、user_id、business_line、first_cc_id、first_cc_name、first_assigned_at、first_outbound_at、first_connected_at、outbound_count、outbound_connected_count、current_cc_id`

- 下载前展示行数、日期范围和时间口径。
- 日期范围明确标注“注册时间”或“首次分配时间”。
- 下载失败时不生成空白或部分文件。
- 联系方式、录音等敏感字段继续沿用现有导出权限，本需求不扩大范围。
- 操作日志记录操作人、筛选条件、数据范围、行数和生成时间。

## 5. RBAC 权限数据

### 功能权限

| 页面 / 动作 | 默认角色 | 数据范围 | 审计 |
|---|---|---|---|
| 团队监控菜单及查看 | 超级管理员、系统管理员、销售组长、业务负责人 | 角色现有业务线、团队或本人范围 | 权限变更记录审计 |
| 团队监控筛选和下钻 | 同上 | 与汇总查看一致；明细继续校验线索权限 | 不单独记录普通查询 |
| 团队监控导出 | 需单独拥有导出权限 | 与查看权限取交集 | 记录操作人、筛选条件、行数和时间 |
| 销售中心首跟字段查看与下载 | 沿用销售中心现有角色 | 沿用现有线索权限，不扩大范围 | 下载记录审计 |

销售专员、推荐运营和自定义角色不因本需求自动获得团队监控权限。系统内置角色新增成员时继承对应角色权限。

### 字段与数据权限

| 资源 | 可见范围 | 编辑 | 导出 |
|---|---|---|---|
| 首跟 CC、首次时间和外呼次数 | 拥有销售中心或团队监控对应查看权限的角色 | 不可编辑 | 需现有导出权限 |
| 用户 ID、联系方式、录音 | 不因本需求扩大可见范围 | 沿用现有规则 | 沿用现有脱敏和导出限制 |
| 团队监控汇总及下钻明细 | 授权业务线、团队或本人范围 | 无 | 需团队监控导出权限 |

历史补数只能通过可审计的数据修复流程完成，不允许直接编辑展示值。

### 权限数据变更

| 变更类型 | 权限层级 | 权限项 | 默认授权 |
|---|---|---|---|
| 新增 | 菜单 | `销售管理 → 团队监控` | 超级管理员、系统管理员、销售组长、业务负责人 |
| 新增 | 页面 | 团队监控查看 | 同上，按角色数据范围 |
| 新增 | 动作 | 团队监控下钻 | 同上，明细继续校验数据权限 |
| 新增 | 导出 | 团队监控导出 | 需显式导出权限 |
| 复用 | 数据 | 业务线、团队和本人范围 | 沿用成员账号现有数据权限 |

菜单、页面、查询、下钻和导出分别校验权限，不能只隐藏前端入口。

## 6. 数据依赖

| 数据 / 系统 | 用途 | 唯一标识 | 失败处理 |
|---|---|---|---|
| 线索与当前负责人 | 当前负责人和销售状态 | lead_id | 失败时保持原负责人及已有历史 |
| 分配历史 | 首跟节点与转派记录 | assignment_event_id | 新事件实时写入；旧事件按可用范围回填 |
| 外呼记录 | 首次外呼、首次接通和次数 | call_id | 事件去重；同步延迟显示最近成功值 |
| 跟进记录 | 跟进状态和操作历史 | followup_id | 幂等写入，不重复计数 |
| 用户与团队 | 权限范围和负责人展示 | user_id、team_id | 不用于推断首跟节点 |
| 导出任务 | 当前范围明细下载 | export_task_id | 失败可重试，不下发不完整文件 |

## 7. 异常与边界

| 场景 | 处理结果 |
|---|---|
| 老数据没有首跟事件 | 显示“历史未知”，不用当前 CC 倒推 |
| 两名 CC 并发领取 | 仅一个成功，仅成功事件写入首跟节点 |
| 写入首跟节点后转派失败 | 保留首跟节点和原负责人 |
| 外呼记录已到、状态未同步 | 写首次外呼时间，首次接通保持为空 |
| 重复回调 | 返回原结果，不重复加次数 |
| 下载超时或失败 | 不生成不完整文件，提示缩小范围或重试 |
| 首跟 CC 离职 | 保留名称快照和 CC ID，展示“已停用” |
| 权限被撤销 | 汇总、明细和导出在下次请求同时失效 |
| 大范围下载 | 沿用现有上限，超限时要求缩小日期范围 |
