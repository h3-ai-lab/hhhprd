# 跟进流程简化项目 Memory

## Confirmed Facts

- `暂不跟进` 是当前跟进阶段之一，不等于退回公海、重新分配或关闭线索。
- 更新跟进入口为 `销售管理 → 销售中心 → 我的跟进 → 更多 → 更新跟进`。
- 当前跟进阶段由“下一步操作”驱动，一条线索同一时间只有一个当前阶段。
- 跟进历史和生命周期事件追加保存，不覆盖原记录。
- 暂停原因属于暂停事件；用户产生新的预约、拒绝或关闭结果后，不应丢失该暂停原因。
- 目标规则按当前阶段决定终态：待外呼、未接通、待预约、暂不跟进使用 `已拒绝`；后续预约及咨询阶段使用 `已关闭`。
- 外呼系统可能把语音信箱识别为已接通。

## Decisions

- 系统删除 `恢复跟进` 动作及其所有新入口。
- 待外呼、未接通或暂不跟进的外呼未接通后自动回写 `未接通`，不打开强制跟进弹窗。
- 已建立预约或咨询结果的阶段不因一次后续未接通回退，只保留外呼事实。
- 外呼接通后打开跟进表单，与手动添加跟进共用同一套动作规则。
- 暂停态开放 `新建跟进`、`暂不跟进` 和当前适用终态动作，默认选择 `暂不跟进`。
- `新建跟进` 是跟进操作，不是跟进状态；本次跟进形成预约后进入 `已预约`。
- 暂停后直接新建跟进或进入终态只记录本次真实业务动作，不补写恢复事件。
- 暂停态再次选择暂不跟进表示保持暂停并追加本次跟进，不重复暂停状态迁移。
- 当前阶段为已预约、未出勤、咨询未完成或咨询已完成时，终态为 `已关闭`。
- 当前阶段为待外呼、未接通、已接通待预约或暂不跟进时，终态为 `已拒绝`。
- 暂停原因新增 `语音信箱`。
- 本期不改列表字段、筛选、排序和导出。
- 原型初始数据必须覆盖待外呼、未接通、已接通待预约、已预约、未出勤、咨询未完成、咨询已完成、暂不跟进、已拒绝、已关闭全部阶段。

## Glossary

- 新建跟进：创建一条跟进记录的操作，本身不是状态；本次记录形成的预约等业务结果才触发阶段更新。
- 保持暂不跟进：线索仍为暂不跟进，仅追加本次跟进说明或调整暂停原因。
- 当前有效预约：已创建、尚未完成出勤或咨询结果处理的唯一预约。
