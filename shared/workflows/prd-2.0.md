# PRD 2.0 工作流

## 目标

用尽量少的往返生成可评审、可开发、可验证的产品定义，并保持 PRD、原型和指标口径一致。

## 执行顺序

1. **需求判级**：判断为简单字段、普通功能、跨模块复杂需求或纯分析。
2. **读取项目上下文**：读取项目 `project.yaml`、`memory/` 和 `rag/sources.yaml`，只加载当前任务相关内容。
3. **读取公共能力**：按需调用 `../skills/crm-prd-authoring`、`crm-prototype-authoring` 和 `crm-artifact-validation`。
4. **形成决策卡**：确认目标、范围、主流程、指标、权限、数据和异常。
5. **冻结关键口径**：字段顺序、排序结论、指标分子分母、RBAC 和原型页面范围必须先明确。
6. **生成交付物**：PRD 默认单文件，放在项目 `prd/PRD.md`；原型放在 `prototype/`。
7. **自动校验**：执行结构、链接、禁用内容和指标一致性检查。
8. **按需发布**：用户要求发布或适用自动发布规则时，由发布 Skill 上传并验证公开 URL。
9. **差异修订**：评审反馈只修改受影响章节或原型模块，不重写全部产物。

## 决策卡

| 项目 | 内容 |
|---|---|
| 业务目标 | 本期要改变的结果 |
| 范围 | 做与不做 |
| 核心流程 | 触发、处理、结果和异常 |
| 指标 | 名称、分子、分母、单位、范围、时间、去重和零值 |
| 权限 | 角色、数据范围、字段和导出 |
| 数据 | 来源、唯一标识、快照和失败处理 |
| 阻塞项 | 只列不解决就无法继续生成的事项 |

## 检索顺序

1. 根目录 `AGENTS.md`
2. 本工作流
3. 项目 `README.md` 和 `project.yaml`
4. 项目 `memory/`
5. 项目 `rag/sources.yaml` 指向的资料
6. 当前 PRD 和原型

## 停止条件

- 业务目标、核心规则或指标定义存在无法自行判断的冲突。
- 无法访问现有 CRM，且现有截图或文档不足以确认字段顺序和筛选位置。
- 新增权限缺少角色或数据范围，继续生成会形成安全风险。

除以上情况外，不重复要求用户确认流程。
