# 项目状态管理

项目状态以 Lark 文档事实为准，不以本地完成、GitHub 发布或原型上线代替。

## 状态

| 状态 | 定义 |
|---|---|
| 待上传 | 本地项目已形成，但 Lark 中没有对应有效文档，或原 Lark 文档已删除 |
| 待评审 | 项目 PRD 已上传到 Lark，且尚未进入评审后修订流程 |
| 评审后修订 | 项目已评审，用户明确要求进行评审后修改，或修订工作已开始 |
| 已废弃 | 用户明确决定停止推进该项目；项目资料保留，不再作为待上传、待评审或待修订工作 |

评审完成且没有修订的最终状态不自动推断，等待用户明确告知后再变更。

## 状态流转

| 事件 | 状态变化 |
|---|---|
| 新建或更新本地项目，但未上传 Lark | 待上传 |
| 将 PRD 首次上传到 Lark，且回读确认成功 | 待上传 → 待评审 |
| 删除 Lark 中的对应文档，且确认删除成功 | 待上传 |
| 上传后继续编辑 Lark 文档内容 | 保持原状态 |
| 用户明确说明已完成评审并要求修改 | 评审后修订 |
| 评审后修订完成并重新上传或覆盖 Lark 文档 | 保持评审后修订 |
| 评审完成且没有修订 | 等待用户指定最终状态 |
| 用户明确决定停止推进项目 | 任意状态 → 已废弃 |
| 用户要求恢复已废弃项目 | 已废弃 → 待上传；后续按正常 Lark 上传和评审流程流转 |

“上传后编辑”包括内容覆盖、标题调整、目录移动和格式修复；这些操作不得自动把状态改为评审后修订。

## 同步范围

状态变化时必须同步：

- `projects/status.yaml`
- 项目 `project.yaml`
- 项目 `README.md`
- 根目录 `README.md`
- `hhhprd-site/index.html`

Lark 文档链接或删除事实记录在 `projects/status.yaml`。

项目管理列表固定排序：

1. 待上传
2. 待评审
3. 评审后修订
4. 已废弃

同一状态内按项目更新时间倒序。

## Lark 上传协作

- Lark 上传继续通过“添加项目PRD到Lark目录”对话，由用户明确指令触发。
- 不改变该对话的触发方式、目录确认方式和命名方式。
- 该对话完成上传、编辑或删除后，项目状态以回读确认的结果同步到本仓库。
- GitHub 发布成功不代表 Lark 已上传，不能据此标记为待评审。
