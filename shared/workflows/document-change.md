# PRD 文档变更流程

## 目标

在不替换整份 PRD 的前提下，按需求所处阶段采用不同变更方式，同时保证原型只展示最新且可用的产品状态。

## 两种变更模式

变更模式以用户明确说明的“评审前修改”或“评审后修改”为准，不能根据“优化”“调整”“修改一下”等表述自行判断。

| 模式 | 适用条件 | PRD 处理 | 原型处理 |
|---|---|---|---|
| 评审前修改 | 需求尚未完成正式评审，当前文档仍是待评审草稿 | 直接修改当前正文，不使用红色、删除线或修订编号，不建立评审后修订记录 | 同步为最新产品状态，不显示变更标记 |
| 评审后修改 | 需求已经完成评审、确认或形成开发基线，后续又发生变更 | 在原 PRD 中标记新增、修改和删除，更新版本与修订记录 | 同步为最新产品状态，不显示变更标记 |

如果用户没有明确说明变更阶段，先确认是评审前还是评审后，不能自行套用文档变更标记。

## 评审后修订

### 版本与标记

在 PRD 顶部记录：

```text
文档修订：v1.1｜基线：v1.0（YYYY-MM-DD）｜本页为本次变更评审版
标记说明：[新增/修改后] 红色表示本版现行内容；[删除/修改前] 删除线表示内容已失效。
```

正文统一使用以下标记：

| 变更类型 | 正文写法 | 含义 |
|---|---|---|
| 新增 | `<ins>[新增] 新内容</ins>` | 本版新增且现行 |
| 修改 | `<del>[原] 原内容</del> <ins>[现行] 修改后内容</ins>` | 删除线仅保留变更证据，红色内容为现行规则 |
| 删除 | `<del>[删除] 原内容</del>` | 原内容已失效 |

Markdown 阅读页会把 `<ins>` 渲染为红色，把 `<del>` 渲染为删除线。文字标签必须保留，不能只依赖颜色表达状态。

### 正文修订规则

1. 在原 PRD 上修改，不重新生成一份无关的新文档。
2. 只标记本次实际变化的段落、表格单元格、流程节点或权限项；未变化内容保持普通样式。
3. 表格中的修改在同一单元格内并列展示原内容与现行内容；整行删除时，逐单元格保留删除标记。
4. 流程图只绘制当前有效流程。被删除的流程线无法可靠显示删除线时，在流程图下方单独列出 `<del>[删除流程] …</del>`。
5. 正文只保留当前修订周期的标记。开始下一次修订前，先清理上一版的红色和删除线：现行内容恢复普通样式，已删除内容从正文移除。
6. 不把历史修订混入当前业务规则；历史明细统一保存在文末修订记录。

### 修订记录

PRD 文末维护累计修订记录，按版本先后追加：

| 编号 | 类型 | 位置 | 变更前 | 变更后 | 对开发的影响 |
|---|---|---|---|---|---|
| R-01 | 新增/修改/删除/术语 | 章节或表格 | 原内容 | 现行内容 | 实现、权限、数据或交互影响 |

修订记录用于长期追溯；正文删除线用于本次评审时快速识别变化，两者不能互相替代。

### 完成回执

评审后修订完成、目标文档写入成功且回读验证通过后，必须生成固定格式回执：

```text
文档修订 vX.X｜文档地址：<最终文档 URL>｜修订内容：<一句话概述本次变更>
```

回执规则：

- 版本必须与 PRD 顶部记录的修订版本一致。
- 文档地址必须是实际更新的最终文档；更新 Lark 时使用 Lark 文档地址，否则使用正式 PRD 在线地址。
- 修订内容必须是一句话，只说明本次最重要的新增、修改或删除，不复述修订记录。
- 更新多个文档时，每个文档分别生成一条回执。
- 只有写入和回读验证成功后才能发送回执；技术提交号、部署状态等可作为补充信息另行报告。

## 原型同步

- PRD 的现行规则变化后，必须同步检查并修改对应原型。
- 原型只展示上线后的最新产品界面和能力，不显示红色、删除线、`[新增]`、`[删除]`、修订编号或变更说明。
- PRD 发生变化但页面交互不受影响时，可以不修改原型，但必须核对页面、字段、指标、权限和交互与 PRD 一致。
- PRD 删除功能时，原型必须同步删除入口、控件、事件处理和权限呈现，不能只修改 PRD。
- 原型地址保持不变，每份 PRD 仍只保留一个完整交互原型地址。

## 执行顺序

1. 确认本次属于评审前修改还是评审后修改。
2. 读取当前 PRD 和对应原型；评审后修改还要读取上一版修订记录。
3. 判断本次变更清单：新增、修改、删除及其影响范围。
4. 评审前直接修订正文；评审后在原 PRD 中修订目标章节并应用正文标记。
5. 评审后更新文档版本、基线日期和本次修订记录；评审前不增加这些标记。
6. 静默同步原型，不向产品界面加入变更标记。
7. 执行结构、链接、指标和 PRD/原型一致性校验。
8. 评审后重新生成 PRD 阅读页并检查红色和删除线渲染。
9. 按发布流程提交、部署并验证公开链接。

## 交付检查

- 评审前修改没有混入红色、删除线、修订编号或修订记录。
- 评审后修改的每项新增、修改和删除都能在正文或修订记录中找到。
- 评审后的修改项同时保留原内容和现行内容。
- 评审后的删除项有明确删除标记，且不再被当作现行规则。
- 正文没有上一修订周期残留的标记。
- 原型没有变更标记，并已反映最新产品规则。
- 评审后修订已生成符合固定格式的完成回执。
