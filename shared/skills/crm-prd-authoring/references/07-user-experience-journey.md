# 用户端体验类 PRD 提示词

先读取 [`../SKILL.md`](../SKILL.md)。

绘制用户端原型时同时读取 [`crm-prototype-authoring`](../../crm-prototype-authoring/SKILL.md)，只展示上线后的真实页面和可操作功能。

## 适用信号

- App、C 端页面、邀请、注册、登录、支付、通知或用户自助操作。
- 用户需要跨多个页面完成一个目标。
- 核心风险是用户不知道下一步、失败后无法恢复或状态反馈不及时。

## 必须回答

- 用户是谁，从哪个入口进入，想完成什么结果。
- 正常步骤、返回、取消、中断和恢复路径。
- 页面文案、默认值、主按钮和次按钮。
- 登录、权限、网络、重复提交和业务失败时看到什么。
- 操作成功后多久展示结果，是否需要通知。
- 移动端布局、无障碍、国际化和时区差异。
- 页面状态和后台业务状态如何对应。
- 敏感信息如何避免在链接、日志和分享卡片中暴露。

## RBAC 权限数据

新增 App/C 端入口、用户状态或运营操作时，必须读取 [`04-permission-audit.md`](04-permission-audit.md)，说明：

- 用户账号、会员、角色或权限变化是否影响页面入口和操作。
- 用户能看到哪些本人、家庭或组织数据。
- 客服、运营和管理员代操作时的权限、数据范围与审计。
- 本次新增、修改或复用的 RBAC 权限项。

## PRD 组织

1. 用户问题和目标结果。
2. 用户旅程总图。
3. 页面与状态。
4. 关键文案和交互。
5. 异常、恢复和通知。
6. 权限与隐私。

## 内部检查

- 每个失败都有下一步和恢复方式。
- 页面状态不会早于后台最终状态。
- 用户不会看到内部错误或敏感数据。
- 用户入口、代操作和敏感数据是否纳入 RBAC。
- 是否混入前端代码、组件实现或验收。
