# 看板与指标类 PRD 提示词

先读取 [`../SKILL.md`](../SKILL.md)。

## 适用信号

- 漏斗、趋势、KPI、同比/环比、经营日报或分析看板。
- 用户需要从汇总数字下钻到明细或下载对账。
- 指标口径、数据时效或业务线范围不清楚。

## 每个指标必须写清

- 指标名称和业务用途。
- 分子、分母、去重维度和过滤条件。
- 时间字段、时区、自然日/自然月或业务周期。
- 业务线、团队、角色等维度。
- 空值、取消、退款、测试用户和异常状态是否纳入。
- 所有市场和数据范围维度统一使用“业务线”，不使用“国家”。
- 数据来源、更新频率和允许延迟。
- 是否支持下钻、明细字段和导出，下钻范围必须与数字一致。
- 是否支持历史回补，回补后看板如何提示变化。

## 指标口径必须可执行（强制）

PRD 中每个指标都必须定义到可以直接计算和核对的程度：

- 写清指标名称、展示位置和业务用途。
- 写清分子、分母和数值单位，并区分“人数/线索数”与“记录数/次数”。
- 写清统计范围、业务线、负责人、时间字段和时间区间。
- 写清去重键；同一指标内使用同一去重键，跨指标复用时保持口径一致。
- 写清空值、无记录、零分母、数据未同步和比率超过 100% 的展示方式。
- 写清汇总、分表、下钻和导出是否使用同一集合。
- 比率类指标必须同时说明分子和分母，不能只写百分比名称。
- 每个指标卡、指标列或指标值右上角必须有“口径”角标；用户点击或悬停后可查看该指标的分子、分母、单位、统计范围、时间字段、去重键和零值规则。

PRD 与原型必须逐项一致：

- 同一个指标在 PRD、原型标题、指标卡、表格和提示中只能使用同一个名称。
- 原型显示的值必须能由 PRD 的分子、分母、统计范围和去重规则计算得出。
- 人数类指标不能使用记录数做分母，记录数指标不能伪装成人均指标。
- 原型每个比率同时展示分子和分母，或展示足以反推分子和分母的两个计数。
- 交付前必须逐项核对 PRD 指标清单与原型中的全部指标卡、表格列和计算值；缺少、重名、改名或公式不一致都视为未完成。

## 离职员工与组织变更（强制）

报表、看板、日报和业绩指标必须说明员工离职、账号停用、调岗或团队变化后的统计规则。

至少覆盖：

- 历史归属基准：使用业务事件发生时的负责人、团队和组织快照，或使用当前组织关系；同一报表必须统一，并明确说明。
- 离职员工保留：停用账号和离职员工仍保留在历史数据与筛选中，显示姓名快照和“离职/停用”状态，不因账号停用而从报表消失。
- 转派不追溯：线索或其他业务对象转给新负责人后，默认不把历史业绩从原负责人整体转到新负责人；如按新负责人重算，必须说明范围和时点。
- 防重复统计：同一业务对象或业务事件只能归属一个负责人；交接日不得同时计入原负责人和新负责人。
- 期间完整性：统计周期内离职时按实际在职区间计入；涉及人均、日均和目标完成率时，同步说明在职人数分母。
- 当前组织与历史组织：组织架构调整后，历史报表使用组织快照还是当前架构必须一致；不能因员工调组让历史总额变化。
- 筛选与导出：历史筛选能定位到离职员工；导出保持相同归属、去重和权限规则，并避免泄漏离职员工敏感信息。
- 权限时效：账号停用后立即失去报表访问和导出能力，但符合数据权限的现任管理者仍可查看其历史业务数据。

## RBAC 权限数据

新增看板、指标或明细下载时，必须读取 [`04-permission-audit.md`](04-permission-audit.md)，说明：

- 哪些角色可以进入看板、看到哪些业务线和数据范围。
- 汇总数字、明细下钻和导出是否使用相同数据权限。
- 手机号、收入、客户明细等敏感字段是否脱敏或禁止导出。
- 本次新增、修改或复用的 RBAC 权限项。

## PRD 组织

1. 业务问题和决策场景。
2. 指标定义表。
3. 筛选、维度和时间口径。
4. 汇总、趋势、漏斗和下钻。
5. 权限、数据时效、离职员工口径和导出。

## 内部检查

- 汇总与明细使用同一过滤、去重和时间口径。
- 看板、下钻和导出使用一致的 RBAC 数据范围。
- 百分比是否来自正确的分子和分母。
- 每个指标是否有明确名称、分子、分母、单位、统计范围、去重键和零值规则。
- 原型中的全部指标是否与 PRD 逐项同名、同公式、同筛选范围和同去重口径。
- 空数据是否不会被展示为真实零。
- 是否定义离职员工、账号停用和归属转派后的统计口径，避免历史数据消失或重复归属。
- 是否混入查询语句、代码或验收。
