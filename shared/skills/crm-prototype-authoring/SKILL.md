# CRM 原型设计

原型用于模拟上线后的真实产品界面，不是 PRD 的可视化排版。页面只保留用户上线后实际会看到和操作的内容。

## 只展示上线后所需功能

允许出现：

- 产品正式导航、页面标题、页签和面包屑。
- 用户实际使用的筛选、排序、搜索、表单、表格、按钮和详情。
- 产品正式提供的指标、状态、字段、提示和异常反馈。
- 真实业务需要的空态、加载态、失败态、权限态和二次确认。
- 可操作的流程切换、详情抽屉、弹窗和提示消息。

禁止出现：

- PRD 式大标题、英文眉题和解释性副标题。
- “本次新增”“当前视图可确认”“原型说明”等设计过程信息。
- 业务背景、需求价值、规则说明、实现思路和流程叙事卡。
- “字段定义”“查看规则”“PRD”“原型”“演示数据”等非生产入口。
- 用大段 Hero、流程步骤、架构图或说明横幅替代真实页面控件。
- 验收清单、测试入口、需求编号和技术注释。

说明性内容留在 PRD。原型打开后应直接进入用户实际工作的默认页面。

## PRD 修订同步

- 已有 PRD 发生新增、修改或删除后，同步检查并修订对应原型。
- 原型只展示最新产品状态，不显示红色、删除线、`[新增]`、`[删除]`、修订编号或变更说明。
- PRD 删除功能时，同步删除原型中的入口、控件、事件处理和权限呈现，不能只修改 PRD。
- 原型变更不增加额外标注；评审后修改的差异由 PRD 正文和修订记录承担，评审前修改直接更新 PRD 正文。

## 页面与交互

- 首屏优先展示实际列表、表单或工作台，不先展示介绍页面。
- 使用真实业务布局、数据密度、字段顺序和操作位置。
- 面向用户的市场和数据范围统一使用“业务线”，不展示“国家”标签。
- 筛选、排序、分页、导出、详情和异常反馈必须可操作。
- 使用演示数据时，不在产品界面额外显示“演示数据”横幅。
- 只有上线产品本身包含帮助说明时，才允许出现说明入口或 Tooltip。

## 指标一致性（强制）

- 原型中的每个指标必须能在 PRD 指标表找到同名、同定义的来源。
- 指标名称、分子、分母、单位、统计范围、时间字段和去重键必须与 PRD 一致。
- 比率指标同时展示分子和分母，或展示能够直接组成该比率的两个计数。
- “外呼线索数”“外呼总次数”“接通线索数”“接通总次数”必须分开表达，不能用同一个标签混用。
- 汇总卡、分表、图表、下钻和导出的数值必须来自同一筛选集合。
- 原型不能自行改名、增减口径或使用不同分母来模拟数据。
- 看板指标卡和指标列右上角必须提供“口径”角标，角标内容与 PRD 的指标定义一致。
- 交付前必须逐项核对 PRD 指标清单与原型所有指标展示，发现不一致时先修订 PRD，再同步原型。

## 视觉要求

- 视觉语言与目标产品保持一致，不加入汇报型排版。
- 卡片用于承载真实业务信息，不用于讲需求故事。
- 指标卡只在指标本身上线后可见时保留。
- 每个页面都应是可直接给开发参考的产品画面，而不是 PRD 摘要。

## 内部检查

- 删除所有业务背景、价值说明、流程叙事和设计提示。
- 页面是否可以从标题直接看出是上线后的真实功能。
- 首屏是否直接进入实际工作，而不是先看介绍。
- 原型指标是否与 PRD 逐项同名、同公式、同范围和同去重口径。
- 原型是否已同步最新 PRD，且没有显示任何文档修订标记。
- 不在原型中输出本检查清单。
