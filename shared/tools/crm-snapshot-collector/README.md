# CRM 只读页面快照采集器

## 解决什么问题

当 Codex 无法直接控制本地浏览器，或 CRM 登录态无法迁移到 Codex 浏览器时，使用这个 Chrome/Edge 扩展在用户自己的已登录浏览器中读取页面结构。

采集结果用于确认：

- 页面路径、标题、导航和页签。
- 筛选项位置、表单字段、按钮和表格表头。
- 页面空态、当前应用名和前端版本。

不采集：

- Cookie、Token、账号密码和接口响应。
- 表格业务行、输入框当前值、客户姓名、手机号、邮箱和下载文件。

## 安装

1. 在 Chrome 或 Edge 打开 `chrome://extensions/`，或 Edge 的 `edge://extensions/`。
2. 打开“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择当前目录：`shared/tools/crm-snapshot-collector/`。
5. 登录 CRM，并停留在需要采集的页面。

## 使用

### 采集当前页面

适合核对一个具体列表、表单或配置页。打开扩展，点击“采集当前页面”，完成后下载 JSON。

### 采集导航发现的页面

适合第一次建立全站基线。扩展从当前页面开始，只沿同一 CRM 域名下、`/dino-omnicenter/` 或 `/omnicenter/` 路径中的页面链接继续执行 GET 导航，不点击新增、编辑、删除、审批、导出、下载等操作。

如果侧边栏或页签不是标准链接，自动发现可能不完整。此时可逐页使用“采集当前页面”，或把需要采集的页面路径发给 Codex 后扩展到路由列表。

## 安全边界

- 扩展只使用用户当前浏览器登录态。
- 扩展不会显示或保存登录凭证。
- JSON 只包含控件和页面结构，遇到邮箱、电话和长数字 ID 会脱敏。
- 快照默认保存在浏览器下载目录，不自动上传。
- 快照不应提交到公开 GitHub 仓库。

## 标准输出

文件名为 `crm-snapshot-<时间>.json`，核心结构：

```json
{
  "schema": "dino-crm-dom-snapshot/v1",
  "capturedAt": "ISO-8601",
  "origin": "https://crm.dinoai.ai",
  "pages": [
    {
      "url": "https://crm.dinoai.ai/dino-omnicenter/...",
      "title": "页面标题",
      "headings": [],
      "tabs": [],
      "buttons": [],
      "formLabels": [],
      "filterLabels": [],
      "tableHeaders": [],
      "navigationLinks": []
    }
  ]
}
```

## Codex 使用规则

- 同日采集、包含目标页面完整控件结构的快照，可作为当前 CRM 页面证据，但必须记录采集时间。
- 超过一个工作日、前端版本变化或页面结构明显不完整时，要求重新采集。
- 快照只能证明页面结构，不能证明后端实时权限、接口返回或数据正确性。
- 仍不得根据历史 PDF、截图或旧手册推测字段顺序和筛选位置。
