# CRM 当前能力与边界

> 基于 2026-11 的 CRM 现状、5.5 需求、管理看板 PRD、一期/三期文档和 11 月 9 日会议整理。
> 更新时间：2026-11-10

> 📌
> - 已有完整“用户 → 线索 → 销售 → 订单 → 看板”骨架。
> - 当前最大风险不是缺页面，而是多渠道、支付、业务线和权限的数据口径不统一。
> - 5.5 计划 2026-11-12 上线，实际发布状态仍需上线当天核验。

## 1. 当前模块

| 模块 | 已经有的能力 | 当前缺口 |
|---|---|---|
| 用户中心 | 用户查询、来源、资料、状态、学习与会员信息、导出 | 注册时间筛选、大导出、五类报告、业务线归属 |
| 销售中心 | 公海、我的跟进、已付费、通话记录、分配/转派/退回/掉库 | 多渠道来源、续费跟进、区域权限、统一线索表 |
| 订单中心 | 订单查询、支付与有效期、主子订单、导出 | 手动转账同步、续费 ID、试用扣款时间 |
| 营销中心 | 渠道、SKU 查询、渠道价格优惠、落地页、皮肤、短链 | 模块边界、短链治理、投放链路 |
| 系统配置 | 角色、成员、功能权限、业务线数据范围、操作日志 | 区域/团队、岗位优先级、敏感操作收敛 |
| 管理看板 | 转化、销售跟进、支付结果、口径、明细下载 | 指标维护、数据时效、统一数据源 |

## 2. 系统边界

| CRM 里看到的能力 | 实际责任方 |
|---|---|
| 用户和登录 | App、注册服务和用户体系 |
| 课程、学习记录、报告 | App、课程和报告服务 |
| 订单、支付、会员 | 支付服务和订单支付服务 |
| 外呼与线路 | 智齿、Omicall 等第三方 |
| 广告线索 | 各广告平台、表单服务和投放系统 |
| 落地页 C 端 | 落地页产品与网站前端 |
| 数仓与 BI | 埋点、数据同步、数仓和 BI |

CRM 主要提供配置、承接、查询和操作入口，不替代上述业务系统。

## 3. 核心业务规则

### 用户与线索

- 已注册、有手机号且未付费的用户可进入销售中心。
- 命中分配规则直接分配；未命中进入公海，由有权限的 CC 领取。
- 超时未付费、超时未跟进或手动退回可重新进入公海或转分配。
- 已注册用户再次留资不重复建号或建 Lead，只追加来源。
- 用户原注册渠道和有效销售归属不能被新渠道覆盖。
- 已付费用户当前保留在销售中心，用于续费跟进。

### 外呼

- 从线索行内调用第三方外呼，CRM 保存通话记录与结果。
- 通话小结、购买意向和下一步由 CC 填写。
- 通话录音、文字稿和 AI 分析不能假设全部已上线。
- 外呼坐席、线路、配额和外显号码由业务配置与第三方共同决定。

### 订单与用户状态

- 订单中心当前主要覆盖会员付费订单。
- 主订单表达当前订单，子订单承载续费、扣费、退款等流水。
- 历史规则曾要求付费后离开销售中心，当前已改为保留供续费跟进。
- 订单状态与用户状态应保持一致，但目前不同支付方式并不同步。

### 权限

- 功能权限由角色配置，数据权限当前以业务线为主。
- 超级管理员有全量权限；普通 CC 主要看本人线索；组长可看组内数据。
- 高敏感能力需要独立授权和审计。

## 4. 在建的 5.5

| 模块 | 能力 | 关键边界 |
|---|---|---|
| 营销中心 | 短链管理 | TinyURL 周期额度；角色、岗位、业务线和创建人共同控制 |

## 5. 已知高风险问题

| 问题 | 影响 | 下一步 |
|---|---|---|
| 手动转账成功后用户状态不同步 | 销售判断和成交统计错误 | 建支付一致性专项 |
| App Store 续费沿用原 Order ID | 订单和续费难区分 | 统一主子订单与唯一 ID |
| 免费试用没有支付时间 | 支付筛选与成交时间异常 | 明确试用、首扣、续费时间 |
| 注册与支付业务线不一致 | 权限、归属和收入统计冲突 | 定义每类业务线优先级 |
| 线索分表存储 | 数仓重复拉取和处理 | 建统一线索表 |
| 区域权限缺失 | 无法按区域隔离客户 | 评估区域/团队权限模型 |
| 部分敏感能力权限与审计不足 | 越权与数据泄露风险 | 权限专项 |

## 6. 核心数据对象

| 对象 | 关键关系 | 待统一 |
|---|---|---|
| 用户 | 来源、线索、订单、学习记录 | 业务线优先级、测试用户 |
| 线索 | 用户、来源、CC、跟进 | 统一模型、去重、来源追加 |
| 来源 | 渠道码、广告层级、表单 | 原始值与标准值映射 |
| 订单 | 用户、商品、支付、子订单 | 续费、试用、手动转账 |
| 通话 | 线索、座席、线路 | 有效外呼口径 |
| 报表 | 用户、课程 | 有效状态与访问权限 |
| 角色/成员 | 业务线、岗位、权限 | 区域/团队与优先级 |

## 7. 后续判断顺序

1. 现有能力是否已经覆盖。
2. 是否是数据、权限或状态一致性缺陷。
3. 是否影响用户、线索、订单或业务线主键。
4. 是否需要第三方或跨团队联调。
5. 是否改变销售归属、支付状态、统计或敏感权限。
6. 是否应放在 CRM，还是投放、商品、支付或数据系统。
